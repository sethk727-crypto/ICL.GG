# ICL.GG — Engineering Roadmap

The working checklist, organized by theme. Items marked **[UI ✓]** already have their
front-end pattern built in this repository — wire them to the PHP/WordPress backend and the
visual layer is done. Items marked **[BE]** are backend work in the main codebase.

---

## 1 · Rosters & event data (BIG fix)

- [BE] Random matchups must be generated by PHP with every client reading from it
  (single source of truth) — small fix, partially done in laptop Codex.
- [BE] Roster resolution happens *before match start* instead of reading the actual roster;
  server does know the rosters — stop reading empty `event_roster_submissions`.
  - Event roster submissions were removed — audit everything that depended on them:
    trade, assign-user-from-blank, reshuffle, draft.
  - Narrow down: LEAGUE-only failure? Some leagues paint, some don't; some teams in a
    league load, some don't. Roster selection must work for both TOURN and LEAGUE.
- [BE] Rosters not loading for USER inside an event — grab from server along with
  get-ready states.

## 2 · Captain authority (medium fix)

- [BE] Captain can post results for teammates. Captain auth is separate (laptop Codex);
  find where teammates get kicked out and use captain auth there instead.
- [UI ✓] Frontend: captain sees the score area for teammates with clear locks
  (demo: "Captain authority confirmed — you can post results for teammates" step in the
  Create Lobby flow, `dashboard.js`).
- [BE] Backend must re-check `is_captain` on every write.

## 3 · Heartbeat & state sync

- [BE] Role-based heartbeat cadence:
  | Role | Auto | Hidden tab | Manual cap |
  |---|---|---|---|
  | Passive player | 90 s | 180–300 s | 1/min |
  | Captain / picker | 30 s (15–20 s on clock) | 90 s | 3/min |
  | Room admin | 20 s | 60–90 s | 6/min |
- [BE] Every heartbeat sends `lastKnownStateVersion` / `savedAtServer`; server answers
  `no_change` unless newer state exists (saves the most bandwidth). Random jitter on auto
  refresh. No heartbeat when the draft panel/page is closed.
- [BE] After heartbeat lands: drafts show REAL users on the clock, not placeholders.
- [BE] 409 races: writes carry a version and retry on conflict —
  `update_option` alone can't detect races unless keys are split.

## 4 · Event engine: tournament ⇄ league merge

- [BE] Merge tournament and league into one **event**: everything resolves through
  `$gd['ctx']` / `_invCtx`; store both league id and tournament id; `currentStage`
  resolves which is active. Slugs merge. PHP stores tournament + league at all times;
  saving saves current.
- [UI ✓] All event settings changeable after creation — entrant count, rounds, single ⇄
  double elim ⇄ round-robin ⇄ Swiss, league ⇄ tournament (demo copy: "Every format. One
  engine." bento card + FAQ answer on `index.html`).
- [BE] After a regular season, roll into a bracket (single room and multi-room).
- [BE] Sort single entrants → controls event counts (JS tells PHP what the next one is).
- [UI ✓] X teams of X (e.g. 4v4v4v4) — *not* a tournament; evolving lobby with drafts,
  trades, reshuffle (demo: ARENA listing on `browse.html` — random teams of 4, no cap).
- [BE] Analysis room per EVENT, not per team.

## 5 · Fair play & records

- [UI ✓] Fair-play/reliability score before launch: score rises for showing up and
  finishing, falls for no-shows and abandons; low scores restrict joining teams/events
  (implemented across lobby cards, challenge rows, rosters, FAQ, verification flows —
  `FP nn` chips everywhere).
- [UI ✓] Track W/L per player and per team like the NFL; records persist after the season
  (implemented: `11–2`-style records on every bracket node, lobby, roster, and team
  listing).
- [UI ✓] Vote to reshuffle teams — majority rules, applies after the current
  match/series (implemented: squad vote card on `dashboard.html`). Vote-for-restart uses
  the same pattern.
- [BE] 60% vote to reassign a misbehaving admin (needs UI later — same vote component).

## 6 · Live streaming (Twitch / YouTube)

- [UI ✓] Twitch styling before phone work: twitch handle next to each member in the
  bracket, next to each match, twitch name on profile (implemented: `tw-mini` chips in
  bracket nodes, handles in stream previews).
- [UI ✓] **Now Streaming** page/strip — advertise it on the front page (implemented:
  streaming strip on `bracket.html`; live-watch bento card on the landing).
- [BE] Polling: on new match, poll Twitch Helix for up to 35 min or until result posted;

- [UI ✓] YouTube as a fallback alongside Twitch (config stub in `assets/js/config.js`).
